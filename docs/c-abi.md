# C ABI guide

Using the C library, `scarletbook-ffi`, from C and other languages. Get it from the
[release assets](releases.md#release-assets) (or build it with Cargo); for Python, see
[Using from Python (ctypes)](python.md). The README's [Quick start](../README.md#quick-start) has a complete program.

## C library

```c
#include "scarletbook.h"
struct SbDisc *disc;
if (sb_disc_open_file("disc.iso", &disc) != SB_STATUS_OK) puts(sb_last_error_message());
```

`sb_build_info()` says how the loaded library was built, for logs and bug reports: a
static string of `key=value` pairs naming its version, target, profile, features, target
CPU features, compiler and commit.

The conventions (status codes, copy-out strings, handle lifetimes, threads) are stated
at the top of `crates/scarletbook-ffi/include/scarletbook.h`;
`crates/scarletbook-ffi/examples/smoke.c` is a complete program. Calls return an
`SbStatus`, an `int32_t`. Every struct field is a fixed-width integer (flags are `uint8_t`,
1 or 0), with these exceptions: the string pointers of `SbWarning`, `SbComment` and
`SbMarker`, the data pointers and `size_t` lengths of `SbPositionData`, and the `double` of
`SbAreaCapacity`. No struct has padding on a 64-bit target. So the layouts stated in the
header hold on every target, except that the four structs with pointers are smaller on a
32-bit target, where `SbWarning` can also end in 4 bytes of padding; the header states each
32-bit layout. The header is generated by cbindgen; see
[Changing the C ABI](contributing.md#changing-the-c-abi).

Beyond `SbDiscInfo`, `SbAreaInfo` and the strings, the master TOC's genres
(`sb_disc_genre`), text channels with their language codes as stored and character set
codes (`sb_disc_text_channel_count`, `sb_disc_text_channel`), catalogue numbers as stored,
padding kept (`sb_disc_catalog_number_stored`), and manufacturer data
(`sb_disc_manufacturer`) have calls of their own, as do an area's version, maximum
available channels, mute flags, track attribute and offset, and text channels
(`sb_area_details`, `sb_area_text_channel`). The area play time and each track's start and
duration are also given as their stored timecode bytes (`SbTimecode`:
`sb_area_playtime_stored`, `sb_track_timecodes_stored`), before any clamping and whatever
their range, beside the frame counts of `SbAreaInfo` and `SbTrackInfo`.
`sb_area_capacity` gives what an area's TOC claims against the audio sectors the image
holds (`SbAreaCapacity`: the sectors present, the play time and largest track end, the
capacity of specification 4, 4.8, the most plain DSD frames those sectors can carry, and
frames per sector), for a plausibility check whose threshold the caller chooses; it reads
nothing.

`sb_disc_read_sectors(disc, lsn, count, buf, cap)` copies the 2048-byte user data of
logical sectors `[lsn, lsn + count)`, whatever the image's stored sector size (2048, 2054
or 2064 bytes): the bytes a 2048-byte-sector copy of the image holds there, for example to
digest the TOC sectors or write such a copy. A range reaching past the last sector fails
whole with `SB_STATUS_SECTOR_RANGE_INVALID`, writing nothing.

### Seeking

A seek index (see [Seeking within an area](rust.md#seeking-within-an-area)) is a handle of its
own, `SbSeekIndex`, tied to an area and image size rather than to a disc handle, so it can
be built on one disc handle and used on another of the same image:

```c
SbSeekIndex *index = NULL;
sb_seek_index_new(disc, slot, SB_SEEK_DEFAULT_INTERVAL, SB_SEEK_DEFAULT_INLINE_BUDGET, &index);
uint8_t complete = 0;
while (sb_seek_index_extend(disc, index, 65536, &complete) == SB_STATUS_OK && !complete) {}
SbTrackAudio *audio = NULL;
sb_range_audio_open_indexed(disc, slot, first, end, index, &audio); /* same frames, few reads */
/* ... sb_track_audio_read ... then hand its new checkpoints back: */
sb_track_audio_absorb(audio, index);
size_t len = 0;
sb_seek_index_save(index, NULL, 0, &len);  /* SB_STATUS_BUFFER_TOO_SMALL, *len set */
/* ... sb_seek_index_save(index, buf, len, &len); later
   sb_seek_index_load(disc, slot, buf, len, SB_SEEK_DEFAULT_INLINE_BUDGET, &index) */
```

`sb_range_audio_open_next_indexed` and `sb_raw_frames_open_next_indexed` continue a handle
through an index; `sb_seek_index_merge` joins indexes built apart.

A disc can also keep the index itself: after `sb_disc_seek_index_enable` (or
`sb_disc_seek_index_set` with a loaded one), every handle opened through the disc or any of
its clones (`sb_disc_clone`) starts from it, and reads build it, with no `_indexed` calls.
The disc and its clones keep one index, so `sb_disc_seek_index_extend` on a clone in a
thread of its own builds it for all of them; `sb_disc_seek_index_get` copies it out to
save. Loaded bytes are checked
before use, and an index that does not match the image's sectors is discarded as it is used
(a warning in the log, then a scan from the area's first sector).

Provisional reading (cold seeks, specification 4, 4.2 item 8) is opt-in per disc handle:
`sb_disc_seek_policy_set(disc, slot, SB_SEEK_POLICY_SPECULATIVE, SB_SEEK_DEFAULT_MIN_GAP)`.
After a handle's first read, `sb_track_audio_speculation` says whether its positions are
provisional (`SbSpeculation`), and `sb_track_audio_suspect` whether the library has reasons
of its own to doubt that reading (`SB_SUSPECT_*`, an informative mark;
`SB_SEEK_POLICY_SPECULATIVE_EXACT_WHEN_SUSPECT` reads those exactly instead). With a seek index kept, `sb_disc_seek_verify` (on a clone in a
thread of its own) checks provisional readings, and `sb_disc_seek_event_next` returns each
verdict once: confirmed, or refuted with the frame from which the positions are exact
(`exact_from`; re-read the positions below it with `SB_SEEK_POLICY_EXACT` for those of a
straight read). A disc that keeps a seek index of the area hands each reading through it to
that index, also for ranges opened with an index of the caller's.

### Output files

The DSF and DSDIFF layouts of [DSF and DSDIFF files](rust.md#dsf-and-dsdiff-files):

```c
SbOutputOptions *opts = NULL;
sb_output_options_new(&opts);
sb_output_options_set(opts, SB_OUTPUT_OPTION_ID3_FOOTER, 0);  /* each writer's choice */
SbOutputLayout *layout = NULL;
sb_output_layout_new(disc, slot, first, end, SB_OUTPUT_FORMAT_DSF, opts, &layout);
SbOutputLayoutInfo info;
sb_output_layout_info(layout, &info);                        /* info.size, from the TOC */
size_t n = 0;
sb_output_layout_read(layout, disc, offset, buf, len, &n);   /* any byte range */
/* or sb_output_layout_positions + sb_output_layout_fill with positions you hold */
```

For DST passthrough, `sb_dst_lengths_scan` (or `sb_dst_lengths_load`) and
`sb_output_layout_new_dst`. For gapless DSF files of consecutive ranges (specification 8,
8.2.7), `sb_output_dsf_chain_plan`, then each file with `SB_OUTPUT_OPTION_DSF_CHAIN_FIRST`
and `SB_OUTPUT_OPTION_DSF_CHAIN_END` set to its entry's `chain_first` and `chain_end`. Tag items: `sb_tags_from_toc`, `sb_tags_set`, `sb_tags_push`,
`sb_tags_remove`, then `sb_output_options_set_tags`. An area whose loudspeaker layout is
unspecified is refused for DSF with `SB_STATUS_OUTPUT_LAYOUT_UNSPECIFIED` unless a channel
type is given, and an edited master that 8.4.11 excludes with `SB_STATUS_NOT_EDITED_MASTER`.

### Parallel decoding

Track and range audio handles decode on the calling thread unless given a pool of
decoding threads:

```c
struct SbPool *pool;
sb_pool_new(4, &pool);                 /* 0: one thread per logical CPU */
sb_range_audio_open(disc, slot, 0, playtime, &audio);
sb_track_audio_set_pool(audio, pool);  /* continuations keep it */
sb_pool_free(pool);                    /* reference-counted: the handle keeps it alive */
while (sb_track_audio_read(audio, disc, buf, cap, &fi) == SB_STATUS_OK) { /* in order */ }
sb_track_audio_free(audio);
```

The calling thread still reads the disc (read callbacks run there) and receives the frames
in order, while the pool decodes DST frames ahead of it; the output is exactly that of the
calling thread. A handle holds at most `16 x threads` frames ahead, never more than 512
(about 48 MB at most). A pool may be shared by handles of several discs read on several
threads. The library creates no global pool; the log callback is also called from the
pool's threads (see `sb_disc_set_log`).

To read one image on several threads at once (for example several tracks of one disc),
give each thread a clone of the disc: `sb_disc_clone(disc, &copy)` shares the parsed TOC
and reads the same file or memory at a position of its own, and a track handle opened from
any clone may be read through any other. A disc opened with read and seek callbacks cannot
be cloned that way: open it with a positional read callback instead
(`sb_disc_open_callbacks_at`, called with an offset, possibly from several threads at once),
or give each clone read and seek callbacks of its own (`sb_disc_clone_callbacks`).

### Stored and decoded frames in one pass

A track or range audio handle can also give each position's stored content, as
`sb_raw_frames_read` gives it, next to its decoded audio, from one read of the area's
sectors (for example to write a file of the stored DST frames and decoded files at once):

```c
sb_range_audio_open(disc, slot, 0, playtime, &audio);
sb_track_audio_set_pool(audio, pool);   /* optional, as for any handle */
sb_track_audio_keep_stored(audio);      /* before the first read */
uint8_t raw[SB_MAX_FRAME_BYTES];
SbRawFrameInfo ri;
while (sb_track_audio_read_with_stored(audio, disc, buf, cap, &fi, raw, sizeof raw, &ri, 0)
       == SB_STATUS_OK) {
  /* buf: as sb_track_audio_read; raw[0 .. ri.size): as sb_raw_frames_read (1 for the last
     argument: as sb_raw_frames_read_dst_equivalent) */
}
```

The decoding runs where the handle decodes, with the same frames held ahead; the frames,
statuses, kinds and counts are those of the two separate handles, and each audio sector is
read once.

### Cancelling and progress

A conversion running on a worker thread can be stopped and followed from another thread,
through two small handles made for that, which several threads may use at once:

```c
SbCancel *token = NULL;
sb_disc_cancel_token(disc, &token);       /* on the disc's thread: shared by its clones */
SbProgress *progress = NULL;
sb_track_audio_progress(audio, &progress); /* on the handle's thread, before reading */
/* worker thread: while (sb_track_audio_read(audio, disc, ...) == SB_STATUS_OK) {...} */
/* other thread: */
uint64_t read, expected;
sb_progress_get(progress, &read, &expected); /* sectors read, sectors expected */
sb_cancel_request(token);                  /* e.g. on Ctrl-C */
```

While cancellation is requested, every call that reads audio sectors through the disc or
its clones returns `SB_STATUS_CANCELLED`, distinct from `SB_STATUS_IO`: at once for a call
that starts then, after at most 32 more sectors for one in progress (or, during the reads
sized to the range after a provisional start or a resume from a seek index, after the read
in progress, of at most 512 sectors, 1 MiB),
the scan before a range's first frame included, whatever the disc reads through (a file, memory or
callbacks). The request is sticky: it holds for the disc and its clones until
`sb_cancel_withdraw` (a disc opened afresh has a token of its own). The handles keep their
state: after `sb_cancel_withdraw` they continue exactly where they stopped; or free them. `sb_progress_get` gives the sectors a handle has read
(exact, updated at least every 32 sectors, or every read of at most 512 sized to a
range after a provisional start or a resume from a seek index, also during the scan before
its first frame)
and the sectors it expects to read (an estimate, equal to the count read once done), for
track, range and raw frames handles. Neither handle borrows the disc or the handle it came
from, so polling it never collides with the reading thread; free each with its `_free`.

### Unreadable sectors

A reader of a damaged disc marks the sectors it could not read (1.2.0, #435). There are two
ways to do it, and both feed one set per disc, which its clones share:

```c
sb_disc_unreadable_add(disc, lsn, count);    /* before opening the handles that read them */
/* or, in a read callback, for bytes it cannot read: */
return SB_READ_UNREADABLE;                   /* -2; any other negative value is an I/O error */
```

Every position whose frame has a byte in a marked sector, or starts in one, is then lost:
`SB_FRAME_STATUS_LOST` in `sb_track_audio_read` (filled with 0x69), and `SB_FRAME_KIND_LOST`
with no bytes in `sb_raw_frames_read`. Its DST equivalent is a missing position's. The
stored frame list gets one `LOST` entry for each lost position below the play time.
`sb_track_audio_lost` and `sb_raw_frames_lost` count lost positions; they are not in the
missing counts. Reading resumes at the next frame that starts in a readable sector, at its
own frame number, and nothing else changes. None of these values appear for a disc with no
marked sectors.

The library never asks the image for a marked sector. When a callback returns
`SB_READ_UNREADABLE`, the library reads the request again one sector at a time and marks
each sector that still fails; `sb_disc_unreadable_range` lists the marked runs.
`sb_disc_read_sectors` refuses marked sectors with `SB_STATUS_SECTOR_UNREADABLE`, and the
seek index extension calls stop at the first marked sector with the same status, because a
seek index's own checkpoints never hold state from past one. Past marked sectors, the index
keeps the state of the reads that met them, each point keyed by the marked runs before it
(#441): the first range opened past a marked sector scans the area from its start, and later
ones start near their first frame while the marks before them stay the same (handles
continued with `_open_next` read on, unless that state starts their range further on, #443).
An index saved with that state
(`sb_seek_index_save`) loads in this and later versions only. `sb_disc_unreadable_remove` unmarks sectors.

`sb_seek_index_without_damage` gives a copy of an index without that state (#443), to save for
a library version that does not load it.
`sb_disc_seek_index_extend_past_marks` and `sb_seek_index_extend_past_marks` build that state
ahead of the reads, in calls of any size (#443), so that the first range opened past a new mark
starts near its first frame too; unlike the extension calls above they don't stop at a mark.

### DSD to PCM

`scarletbook-pcm` is decommissioned
([#398](https://github.com/aclater/scarletbook-rs/issues/398)): frozen at 0.7.0 on crates.io,
no further releases. The `sb_pcm_*` functions, which wrap it, are deprecated from
scarletbook-ffi 1.1.0: the header declares them with `SB_DEPRECATED`, so C and C++ compilers
warn where they are called (define `SB_DEPRECATED(msg)` as nothing to silence it). They keep
working, unchanged, and stay in ABI 2; removing them would take a new `SB_ABI_VERSION`.
Instead, take the DSD from `sb_track_audio_read` and convert it to PCM in your own code, as
the consumers in #398 do with their own crate.

The library also converts the decoded DSD64 audio to 24-bit PCM (crate
`scarletbook-pcm`) at 88.2, 176.4 or 352.8 kHz, through a converter handle that belongs
to no disc:

```c
SbPcmConverter *conv = NULL;
sb_pcm_converter_new(176400, SB_PCM_CUTOFF_DEFAULT, channels, 0.0 /* dB */, &conv);
uint32_t spf;                              /* output samples per channel per frame */
sb_pcm_samples_per_frame(conv, &spf);      /* 1176, 2352 or 4704 */
/* prev, cur, next: frames f - 1, f, f + 1 of the area from sb_track_audio_read (prev NULL
 * at the area's first frame, next NULL at its last); each channels x 4704 bytes. */
uint64_t clipped[6];
sb_pcm_convert_run(conv, prev, cur, channels * 4704, next, SB_PCM_S24LE,
                   pcm, (size_t)spf * channels * 3, clipped);
sb_pcm_converter_free(conv);
```

A frame is 4704 bytes per channel, 37 632 one-bit samples (1/75 s). `sb_pcm_convert_run`
converts a run of whole frames (one frame, or a whole area with both neighbours NULL) into
`frames x spf x channels` interleaved samples of 4 bytes (`SB_PCM_S32`, an `int32_t`
sign-extended from 24 bits) or 3 (`SB_PCM_S24LE`, the layout of 24-bit WAV and FLAC); with
`out` NULL or too short it returns `SB_STATUS_BUFFER_TOO_SMALL` and writes nothing. The
cutoffs are `SB_PCM_CUTOFF_DEFAULT` (passband to 40 kHz), `SB_PCM_CUTOFF_LOW` (30 kHz) and
`SB_PCM_CUTOFF_WIDE` (80 kHz, at 176.4 and 352.8 kHz only); the gain is -120 to +24 dB, and
`clipped` (or NULL) receives the samples of each channel clamped to 24 bits.

The output depends only on the input bits: frame f converted with frames f - 1 and f + 1
as neighbours is byte for byte frame f of a conversion of the whole area. So frames can be
converted in any order, on any number of threads (one converter each), and a seek needs
only the frames around it. The filters, their measured response and the throughput are in
the crate's [README](../crates/scarletbook-pcm/README.md).

From Python, with the bindings of [Using from Python (ctypes)](python.md):

```python
conv, spf = H(), C.c_uint32()
check(lib.sb_pcm_converter_new(176400, 0, 2, 0.0, C.byref(conv)))  # SB_PCM_CUTOFF_DEFAULT
check(lib.sb_pcm_samples_per_frame(conv, C.byref(spf)))
pcm, clipped = C.create_string_buffer(spf.value * 2 * 3), (C.c_uint64 * 6)()
check(lib.sb_pcm_convert_run(conv, prev, cur, len(cur), nxt, 1, pcm, len(pcm), clipped))  # SB_PCM_S24LE
lib.sb_pcm_converter_free(conv)
```

## Linking

```sh
# Static: the archive, then the system libraries it needs.
cc app.c -I$PKG/include $PKG/lib/libscarletbook_ffi.a $(cat $PKG/native-static-libs.txt)
# Shared: ship libscarletbook_ffi.so.2 (0.5.9 and earlier: libscarletbook_ffi.so) next to the
# program, or set an rpath.
cc app.c -I$PKG/include -L$PKG/lib -lscarletbook_ffi -Wl,-rpath,'$ORIGIN'
```

From 0.6.0 on, the shared library's name carries the C ABI version, `SB_ABI_VERSION`, not the
crate version (see [ABI compatibility](#abi-compatibility)). Releases up to 0.5.9 ship only the unversioned file, and
a program records that name. From 0.6.0:

| | Name a program records | The file | Link for the linker |
|---|---|---|---|
| Linux | SONAME `libscarletbook_ffi.so.2` | `libscarletbook_ffi.so.2` | `libscarletbook_ffi.so` |
| macOS | install name `@rpath/libscarletbook_ffi.2.dylib`, compatibility version 2.0.0 | `libscarletbook_ffi.2.dylib` | `libscarletbook_ffi.dylib` |
| Windows | `scarletbook_ffi.dll` (not versioned) | `scarletbook_ffi.dll` | `libscarletbook_ffi.dll.a` (import library) |

`-lscarletbook_ffi` finds the unversioned link and the program records the versioned name, so
**the versioned file is the one to ship**, found through the program's rpath
(`-Wl,-rpath,@loader_path` on macOS). Copy it under that name; such a program does not need the
link at run time. A program linked against a release before 0.6.0 recorded the unversioned name,
so it does need the link, next to the library, until it is relinked. A library loaded by path, as
with ctypes, loads under either name while the link is there. See
[Migrating to 0.6.0](migrating-0.6.md#m8-the-shared-librarys-name).

Windows has no SONAME: a program records the DLL's file name. `scarletbook_ffi.dll` keeps its
name, because integrators ship it next to their program, so `sb_abi_version()` is the only
check there. With MinGW-w64 GCC, `-lscarletbook_ffi` picks the import library (`.dll.a`), so
the program needs `scarletbook_ffi.dll` at run time; link the static library by its path
instead to avoid that.

Only the release archives are named this way, by `.github/scripts/clib-package.sh`. A plain
`cargo build` makes `libscarletbook_ffi.so` with no SONAME at all. To build one with the SONAME
from source, for example for a system package, add what the script adds and install it under
that name:
`cargo rustc --release -p scarletbook-ffi --lib -- -C link-arg=-Wl,-soname,libscarletbook_ffi.so.2`.


## ABI compatibility

**ABI 2 is the 1.0 ABI** ([#39](https://github.com/aclater/scarletbook-rs/issues/39), owner
decision of 2026-11-06). 1.0.0 has `SB_ABI_VERSION` 2, and no ABI 3 is planned: no planned
work needs an ABI 2 struct to grow, because new data comes through new functions and types. On
Linux and macOS the shared library is named after this number (see [Linking](#linking)), so
`libscarletbook_ffi.so.2` and `libscarletbook_ffi.2.dylib` are the 1.0 names too.

The ABI is everything `scarletbook.h` declares (functions and their signatures, struct
layouts, enum names and values, macros) and the behaviour the header documents.
`SB_ABI_VERSION` in the header, `sb_abi_version()` in the library and the number in the shared
library's name on Linux and macOS all number its breaking changes:

- **Additions keep `SB_ABI_VERSION`**: new functions, new types, new enum values (status
  codes included: treat a status you do not know as a failure) and new macros. A program
  built against an older header keeps working with the newer library.
- **Breaking changes increment `SB_ABI_VERSION` by one**: removing or renaming a
  declaration, changing a signature, changing a struct's layout (adding a field included:
  callers allocate the structs), changing an enum value, or changing documented behaviour
  incompatibly. The check below compares declarations as text, so it also counts renaming
  a parameter and reordering existing declarations as breaking; avoid both.
- Comments and documentation fixes that do not change behaviour are not ABI changes.

Releases follow this:

- a **patch** release (`x.y.Z`) does not change the ABI;
- a **minor** release (`x.Y.0`) may add to it, never break it;
- only a **major** release (`X.0.0`) may break it, and then increments `SB_ABI_VERSION` and,
  with it, the number in the library's name, so libraries of two ABIs can sit side by side.

While the version is `0.y.z`, as in Cargo, the `y` step is the major one and the `z` step
the minor one, so there are no patch releases before 1.0.

The `-v3` archives of a release carry the same ABI as its baseline archives, at the same
`SB_ABI_VERSION`, library name and `sb_version()`; they differ only in the instruction set (see
[Release assets](releases.md#release-assets)), which the ABI does not cover. A program can switch between the two
without rebuilding, but must check the CPU before it loads the `-v3` library.

A program checks `sb_abi_version() == SB_ABI_VERSION` before using the library. Since
additions keep `SB_ABI_VERSION`, a program that needs a function added in a later minor
release also checks `sb_version()`: the library must be at least that release. A program
that loads the library at run time can look the symbol up instead.

| `SB_ABI_VERSION` | First release |
|---|---|
| 1 | 0.1.0 to 0.3.0 (additions only in 0.3.0) |
| 2 | 0.4.0 (additions in 0.4.1, 0.5.0, 0.5.1, 0.5.2, 0.5.4, 0.6.0, 1.2.0 and 1.3.0); unchanged from 0.6.1 to 1.1.1 (1.1.0 deprecates the `sb_pcm_*` functions, which stay in it); the 1.0 ABI |

CI enforces this; how is in [Changing the C ABI](contributing.md#changing-the-c-abi).

### From ABI 1 to ABI 2

ABI 2 (0.4.0) removes the declarations whose size or layout C leaves to the compiler, so
that every binding (ctypes, cffi, other languages) can follow the header exactly. Every
struct has the same layout on every target, except where it holds a pointer or a `size_t`:
`SbWarning`, `SbComment`, `SbMarker` and `SbPositionData` are smaller on a 32-bit target,
and the header gives both sizes. No function was added, removed or renamed. A C
program that uses the header's names needs changes only where it writes `enum SbStatus`
or passes a `bool *` for `complete`, then recompiles; a binding that spells out the types
follows every point:

- **Status.** Functions return `SbStatus`, now an `int32_t` (in C23 and C++, an
  enumeration with `int32_t` as its underlying type) instead of `enum SbStatus`. The
  `SB_STATUS_*` values are unchanged. Declare variables as `SbStatus`, not
  `enum SbStatus`; in ctypes, `restype = c_int32`. The other enumerations (`SbSlot`,
  `SbFrameStatus`, `SbFrameKind`, `SbDiscString`, `SbAreaString`, `SbTrackString`) are
  likewise `uint32_t`, as their arguments and fields already were.
- **Flags.** `SbDiscInfo.hybrid`, `SbDiscInfo.manufacturer_sector`, `SbTrackInfo.has_genre`
  and the `*complete` out-parameter of `sb_seek_index_extend`, `sb_seek_index_frontier`
  and `sb_disc_seek_index_extend` are `uint8_t` (1 or 0) instead of `bool`; pass a
  `uint8_t *` for `complete`. The header no longer includes `<stdbool.h>`.
- **Sizes.** `SbFrameInfo.size` and `SbRawFrameInfo.size` are `uint32_t` (at most
  `SB_MAX_FRAME_BYTES`) instead of `size_t`. The `inline_budget` arguments of
  `sb_seek_index_new`, `sb_seek_index_load` and `sb_disc_seek_index_enable`, and
  `sb_seek_index_memory`'s `*bytes`, are `uint64_t`, and so is
  `SB_SEEK_DEFAULT_INLINE_BUDGET`. `size_t` remains only for the lengths of caller
  buffers.
- **Layouts.** No struct has padding. `SbDiscInfo` starts with `sectors` (32 bytes, was
  40); `SbTrackInfo` ends with `uint8_t reserved[3]` (still 28 bytes); `SbWarning` is
  `lsn`, `slot`, `track`, `code` (still 24 bytes on 64-bit targets); `SbFrameInfo` is 16
  bytes (was 24) and `SbRawFrameInfo` 12 (was 16). Code that names the fields needs no
  change; a binding that lists them follows the new order.
- **`sb_dst_decode`** refuses a frame longer than `SB_MAX_FRAME_BYTES` (65 536 bytes,
  the reassembly limit of specification 4, 4.4.3) with `SB_STATUS_INVALID_ARGUMENT`,
  before reading it, instead of decoding it with memory proportional to its length.
  Frames from `sb_raw_frames_read` are never longer.

The check `sb_abi_version() == SB_ABI_VERSION` refuses a library of the other ABI either
way round.
