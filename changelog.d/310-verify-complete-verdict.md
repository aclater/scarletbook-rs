Fixed
- `Disc::verify_speculation` and C `sb_disc_seek_verify` could report complete while a provisional reading registered by another disc during the call had no verdict and no event. Code relying on the old promise may have seen an unverified reading treated as complete. They now report not complete until a later call has checked it, so existing `while !verify_speculation(..)` loops finish the job; each call still makes one round within its `max_sectors`. Complete covers the readings the index held at the call's last look: one that joins later has no verdict until a later call, so a caller that must have every verdict runs the loop once more after its readers finish and checks each reading. `extend_seek_index` still reports only whether the index is complete. No delivered frame changes (#310, #PR).
- `Disc::extend_seek_index`, `Disc::verify_speculation` and their C forms made no progress from an empty kept index when `max_sectors` was at most the index's interval: `AreaIndex::merge` dropped the first checkpoint, so a loop over them never ended. Every call now adds a checkpoint, as documented, including at `max_sectors` 0 (#310, #PR).
