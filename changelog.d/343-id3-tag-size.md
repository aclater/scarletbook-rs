Fixed
- A DSF ID3 tag that `output_layout` builds now counts its 10-byte header and its footer or padding against `MAX_TAG_BYTES` (1,048,576 bytes, header and footer included), as a caller's raw tag always has. With the footer (the default) a built tag could be up to 20 bytes over the maximum, a tag the library itself refuses as a raw tag; such a tag is now refused with `Error::InvalidArgument("the tag is larger than MAX_TAG_BYTES")` (`SB_STATUS_INVALID_ARGUMENT` from the C API). Without a footer the check counted 10 bytes too many, so a tag of 1,048,567 to 1,048,576 bytes with padding was refused; it is now written. A tag of exactly `MAX_TAG_BYTES` is written either way, and reads back unchanged as a raw tag (#343, #348).
