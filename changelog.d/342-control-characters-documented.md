Changed
- The documentation now names every accessor that can return a control character, in the Rust docs and on each C function that returns these strings. ISRCs (`Track::isrc`, `SB_TRACK_STRING_ISRC`) and catalogue numbers (`MasterToc::album_catalog_number`, `disc_catalog_number`, `SB_DISC_STRING_*_CATALOG_NUMBER`) keep C0, DEL and C1 (specification 2, 2.6.5 item 4). Language codes (`Locale::language`; `SbTextChannel.language` in C) keep every character but trailing NUL and space, U+0000 included (2.5.1 item 1). Disc, area and track text (`DiscText`, `AreaText`, `TrackText`; `sb_disc_string`, `sb_area_string`, `sb_track_string`, `sb_disc_toc`) replace C0 with a space, so ESC is the only escape-sequence starter removed, but keep U+007F and U+0080 to U+009F (2.6.4 item 3). The docs give U+009B (CSI) as an example: it starts a terminal control sequence on terminals that honour 8-bit controls. They say that callers that print these values or put them in tags or file names should escape or filter them for that use. For C they say that `*len` and `SbTocStr.length` give the authoritative length (not strlen), and that language codes are two bytes that are not NUL-terminated. They point to the stored-byte accessors where they exist. Documentation only; no behaviour change (#342, #359).
