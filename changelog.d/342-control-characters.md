Changed
- Control characters no longer reach callers in any TOC string. The ISRCs, both catalogue numbers and the language codes (`Locale::language`) now have every C0 (0x00 to 0x1F), 0x7F and C1 (0x80 to 0x9F) character removed before surrounding whitespace is trimmed; before, only that whitespace was trimmed and an ESC, BEL or line break stayed in the string. An ISRC that is nothing but control characters is now absent, and such a catalogue number or language code is the empty string. In disc, area and track text, U+007F and U+0080 to U+009F now become a space, as C0 already did. The rule applies to decoded code points: multi-byte text (Shift_JIS-X0213, EUC-KR, EUC-CN, Big5) whose bytes fall in 0x80 to 0x9F decodes as before. The C API returns the same strings (`sb_disc_string`, `sb_area_string`, `sb_track_string`); the stored bytes (`album_catalog_number_stored`, `Locale::language_code`, `sb_disc_catalog_number_stored`, `SbTextChannel::language`) are unchanged. This departs from sacd-spec 2.5.1 item 1, 2.6.4 item 3 and 2.6.5 item 4, which keep these characters; no corpus case holds one. It changes what some damaged discs return; undamaged discs read as before (#342, #358).
