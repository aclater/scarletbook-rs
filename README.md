# scarletbook-rs

A clean-room, permissively licensed Rust library for reading Super Audio CD
(Scarletbook) disc images, written only from the specifications and conformance
corpus of [aclater/sacd-spec](https://github.com/aclater/sacd-spec).

Work in progress, built in stages (one pull request each): TOC and sector detection,
audio sector multiplexing, DST decoding, C FFI. The clean-room record is in
[CLEANROOM.md](CLEANROOM.md).

## Layout

| Path | Content |
|---|---|
| `crates/scarletbook` | the library (`#![forbid(unsafe_code)]`, no I/O beyond the reader it is given) |
| `crates/scarletbook-ffi` | the C ABI (`include/scarletbook.h`, generated by cbindgen; `libscarletbook_ffi.{a,so,dylib}`, `scarletbook_ffi.dll`); see [C library](#c-library) |
| `crates/scarletbook-bench` | `bench`, the benchmark program of sacd-spec `benchmarks/README.md` |
| `crates/scarletbook-conformance` | the corpus runner and `scarletbook-toc`, which prints a TOC as manifest-shaped JSON |
| `corpus/` | the sacd-spec conformance corpus, copied unchanged (CC0-1.0) |
| `fuzz/` | cargo-fuzz targets, seeded from the corpus |

```sh
cargo test --workspace                      # includes every corpus case
cargo run -p scarletbook-conformance --bin scarletbook-toc -- corpus/images/hostile-base.iso
```

## Using the library

```rust
use std::{fs::File, io::BufReader};
use scarletbook::{Disc, Slot};

let mut disc = Disc::open(BufReader::new(File::open("disc.iso")?))?;
for frame in disc.track_audio(Slot::TwoChannel, 1)? {
    let frame = frame?; // C x 4704 bytes of interleaved DSD, DST already decoded
}
// Any frame range [first, end) of an area's timeline, pauses included: here the whole area,
// then track 2 with the pause after it.
let area = disc.toc().area(Slot::TwoChannel).ok_or(scarletbook::Error::NoSuchArea(Slot::TwoChannel))?;
let playtime = area.playtime_frames();
for frame in disc.range_audio(Slot::TwoChannel, 0, playtime)? {
    let frame = frame?;
}
let (first, end) = disc.track_range_with_pause(Slot::TwoChannel, 2)?;
for frame in disc.range_audio(Slot::TwoChannel, first, end)? {
    let frame = frame?;
}
```

Features: `parallel` decodes DST frames on rayon's thread pool, ahead of the caller.

## C library

```c
#include "scarletbook.h"
struct SbDisc *disc;
if (sb_disc_open_file("disc.iso", &disc) != SB_STATUS_OK) puts(sb_last_error_message());
```

The conventions (status codes, copy-out strings, handle lifetimes, threads) are stated
at the top of `crates/scarletbook-ffi/include/scarletbook.h`;
`crates/scarletbook-ffi/examples/smoke.c` is a complete program. Regenerate the header with
`cbindgen --config cbindgen.toml --crate scarletbook-ffi --output include/scarletbook.h`
in `crates/scarletbook-ffi` (cbindgen 0.29.4; CI checks the committed header).

### Release assets

Each release carries the C library as `scarletbook-ffi-<version>-<target>.tar.gz`, with a
SHA-256 file `scarletbook-ffi-<version>-<target>.tar.gz.sha256`. Every one is built and
tested on its platform (`.github/workflows/clib.yml`): a C program linked statically and
dynamically, and Python's ctypes, decode a corpus image and compare TOC and audio with the
conformance manifest.

| `<target>` | Runs on | Built in |
|---|---|---|
| `x86_64-unknown-linux-gnu` | glibc 2.17 or later (manylinux2014) | manylinux2014 image |
| `aarch64-unknown-linux-gnu` | glibc 2.17 or later (manylinux2014) | manylinux2014 image |
| `x86_64-unknown-linux-musl` | musl 1.2 or later (musllinux_1_2), with `libgcc_s.so.1` | musllinux_1_2 image |
| `aarch64-unknown-linux-musl` | musl 1.2 or later (musllinux_1_2), with `libgcc_s.so.1` | musllinux_1_2 image |
| `x86_64-apple-darwin` | macOS 10.12 or later | `MACOSX_DEPLOYMENT_TARGET=10.12` |
| `aarch64-apple-darwin` | macOS 11.0 or later | `MACOSX_DEPLOYMENT_TARGET=11.0` |
| `x86_64-pc-windows-gnu` | Windows 10 or later; links with MinGW-w64 GCC | MinGW-w64 target |

The glibc builds are linked against glibc 2.17 itself, inside the manylinux2014 image, and
the build fails if the shared library asks for a newer glibc symbol version. The
macOS minimums are Rust's own for those targets. The Windows build uses Rust's MinGW-w64
target because its static library (`libscarletbook_ffi.a`) and import library
(`libscarletbook_ffi.dll.a`) are in the format MinGW-w64 GCC links; the DLL exports every
`sb_*` function (checked in CI) and depends only on Windows system DLLs.

An archive unpacks to:

```
scarletbook-ffi-<version>-<target>/
  include/scarletbook.h
  lib/libscarletbook_ffi.a           static library (every target)
  lib/libscarletbook_ffi.so          shared library (Linux)
  lib/libscarletbook_ffi.dylib       shared library (macOS)
  lib/scarletbook_ffi.dll            shared library (Windows) ...
  lib/libscarletbook_ffi.dll.a       ... and its import library
  native-static-libs.txt             system libraries to link after the static library
  README.txt, LICENSE-MIT, LICENSE-APACHE
```

### Verifying a download

```sh
sha256sum -c scarletbook-ffi-<version>-<target>.tar.gz.sha256      # macOS: shasum -a 256 -c
gh attestation verify scarletbook-ffi-<version>-<target>.tar.gz -R aclater/scarletbook-rs
```

The attestation (a signed SLSA build provenance statement naming the workflow run and
commit that built the file) exists once the repository is public; until then releases are
published without one.

### Linking

```sh
# Static: the archive, then the system libraries it needs.
cc app.c -I$PKG/include $PKG/lib/libscarletbook_ffi.a $(cat $PKG/native-static-libs.txt)
# Shared: ship the library next to the program, or set an rpath.
cc app.c -I$PKG/include -L$PKG/lib -lscarletbook_ffi -Wl,-rpath,'$ORIGIN'
```

The Linux shared library has the SONAME `libscarletbook_ffi.so` and the macOS one the
install name `@rpath/libscarletbook_ffi.dylib`, so a program finds them through its rpath
(`-Wl,-rpath,@loader_path` on macOS). With MinGW-w64 GCC, `-lscarletbook_ffi` picks the
import library (`.dll.a`), so the program needs `scarletbook_ffi.dll` at run time; link the
static library by its path instead to avoid that. The DLL uses the Universal C Runtime
(`api-ms-win-crt-*.dll`), part of Windows 10 and later. From Python:

```python
import ctypes
lib = ctypes.CDLL("/path/to/libscarletbook_ffi.so")   # .dylib, or scarletbook_ffi.dll
lib.sb_abi_version.restype = ctypes.c_uint32
assert lib.sb_abi_version() == 1   # the SB_ABI_VERSION you wrote your bindings for
```

`.github/scripts/clib-smoke.py` is a fuller ctypes example (structs, strings, audio).

### ABI compatibility

The ABI is everything `scarletbook.h` declares (functions and their signatures, struct
layouts, enum names and values, macros) and the behaviour the header documents.
`SB_ABI_VERSION` in the header, and `sb_abi_version()` in the library, identify it:

- **Every change to the ABI increments `SB_ABI_VERSION` by one**, in the same change,
  whether or not it is compatible. Comments and documentation fixes that do not change
  behaviour are not ABI changes.
- A **patch** release (`x.y.Z`) does not change the ABI.
- A **minor** release (`x.Y.0`) may only extend it compatibly: add functions, add values to
  enums the caller passes in, add macros. It does not remove or rename anything, change a
  signature, change an existing struct (callers allocate them, so structs never grow),
  renumber an enum, or change documented behaviour incompatibly. A program built against
  the older header keeps working with the newer library. New status codes count as
  incompatible unless a function's documentation already allows unknown codes.
- Incompatible changes happen only in a **major** release (`X.0.0`). While the version is
  `0.y.z`, as in Cargo, the `y` step is the major one and the `z` step the minor one, so
  there are no patch releases before 1.0.
- A program should check `sb_abi_version() == SB_ABI_VERSION` (or, if it accepts newer
  libraries, compare against the table below) before using the library.

| `SB_ABI_VERSION` | First release | Compatible with |
|---|---|---|
| 1 | 0.1.0 | (first released ABI; unchanged in 0.2.0) |

CI enforces the first rule: `crates/scarletbook-ffi/abi/abi-N.txt` is a snapshot of the
declarations of ABI version N (comments and layout removed), and
`.github/scripts/abi-check.py` fails when the header differs from the snapshot of its
`SB_ABI_VERSION`. After an ABI change, increment `SB_ABI_VERSION` in
`crates/scarletbook-ffi/src/lib.rs`, regenerate the header, run
`python3 .github/scripts/abi-check.py --write` to add the new snapshot, and add a row to
the table. Snapshots of earlier versions are never edited. Behaviour changes that leave the
declarations alone are not visible to the check and are caught in review.

## Benchmarks

`bench` implements the interface of sacd-spec `benchmarks/README.md`:

```sh
cargo build --release -p scarletbook-bench
target/release/bench decode disc.iso --area 2ch --threads 0 --sink hash   # or null, or raw DIR
```

Pushing a version tag (`v0.1.0`, matching the crate version) runs the release workflow:
it publishes `bench-<version>-x86_64-linux.tar.gz` (generic x86-64, cargo profile `dist`),
after the correctness gate has passed on that very build, and two labelled builds,
`-v3` (`-C target-cpu=x86-64-v3`) and `-znver5` (AMD Zen 5), each with a SHA-256 checksum and, once the repository is public, a signed
build provenance attestation:

```sh
gh attestation verify bench-<version>-x86_64-linux.tar.gz -R aclater/scarletbook-rs
```

## Measuring performance

Two criterion benchmarks track the decoder between releases:

```sh
cargo bench -p scarletbook --bench dst_frames             # DstDecoder::decode, one frame per iteration
cargo bench -p scarletbook --bench dst_frames -- stress/2ch
cargo bench -p scarletbook-conformance --bench pipeline   # Disc::open + TrackAudio, in-memory images
```

- `dst_frames` reports the time per frame and symbols per second (37 632 x channels per
  frame) for two sets, per channel count: `corpus/Nch`, every coded DST frame of the corpus
  images `dst-*.iso` that decodes; and `stress/Nch-LAYOUT`, 2- and 6-channel frames
  generated at start-up by the annex 5.A encoder of `crates/scarletbook/tests/common/dst_enc.rs`
  from a seeded sigma-delta signal (order-128 filters, order-32 filters, and a layout with
  several filter and ptable segments). The stress frames are identical on every run.
- `pipeline` reads every track of a 2-channel and a 6-channel area of small synthetic
  images (plain DSD, DST, DST in 2064-byte sectors) on one thread.

The scripts in `perf/` need Linux and `perf`:

| Script | What it does |
|---|---|
| `perf/cycles-per-symbol.sh [NAME...]` | cycles, instructions, IPC per decoded symbol and ms per frame for `dst_frames` benchmarks, from `perf stat` |
| `perf/flamegraph.sh NAME [OUT.svg]` | `perf record` and inferno (`cargo install --locked inferno --version 0.12.8`) flame graph of `DstDecoder::decode` |
| `perf/compare.sh REV_A REV_B [FILTER]` | builds two revisions (`.` is the working tree) into separate target directories, runs `dst_frames` alternately, pinned, and prints per-benchmark and per-group changes |
| `perf/build-configs.sh` | builds `bench` in several release configurations (LTO, codegen units, PGO) for generic x86-64, x86-64-v3 and znver5, and times single-thread decoding on synthetic images, alternately, pinned, best of several rounds |
| `perf/pgo.sh TARGET_DIR` | a deterministic profile-guided build of `bench` (needs `rustup component add llvm-tools-preview`) |

Pinning: run on an otherwise idle machine and pin to one CPU (the scripts use `taskset`,
CPU 2 by default; set `CPU=`). Turbo and frequency scaling still move results by a few
per cent between sessions, so compare only figures taken in one session, alternately, as
`compare.sh` does. `RUSTFLAGS="-C target-cpu=znver5"` builds for the measuring machine's CPU.

Which figures count: these benchmarks are for development and catch regressions; the corpus
frames are small test streams and the stress frames are synthetic. The figures against the
targets come only from the benchmark rounds on real discs recorded in sacd-spec
`benchmarks/README.md`. CI only compiles the benchmarks; it never times them.

Minimum supported Rust version: 1.85.
