A clean-room, permissively licensed Rust library for reading Super Audio CD
(Scarletbook) disc images, written only from the specifications and conformance
corpus of [aclater/sacd-spec](https://github.com/aclater/sacd-spec).

Work in progress, built in stages (one pull request each): TOC and sector detection,
audio sector multiplexing, DST decoding, C FFI. The clean-room record is in
[CLEANROOM.md](CLEANROOM.md); before contributing, read
[CONTRIBUTING.md](CONTRIBUTING.md), which explains the clean-room rule. Changes are listed
in [CHANGELOG.md](CHANGELOG.md), and vulnerabilities are reported as described in
[SECURITY.md](SECURITY.md).

## Using the library

```rust
use std::{fs::File, io::BufReader};
use scarletbook::{Disc, Slot};

let mut disc = Disc::open(BufReader::new(File::open("disc.iso")?))?;
for frame in disc.track_audio(Slot::TwoChannel, 1)? {
    let frame = frame?; // C x 4704 bytes of interleaved DSD, DST already decoded
}
// Any frame range [first, end) of an area's timeline, pauses included: here the whole area,
// then track 2 with the pause after it.
let area = disc.toc().area(Slot::TwoChannel).ok_or(scarletbook::Error::NoSuchArea(Slot::TwoChannel))?;
let playtime = area.playtime_frames();
for frame in disc.range_audio(Slot::TwoChannel, 0, playtime)? {
    let frame = frame?;
}
let (first, end) = disc.track_range_with_pause(Slot::TwoChannel, 2)?;
for frame in disc.range_audio(Slot::TwoChannel, first, end)? {
    let frame = frame?;
}
```

### Stored content (DSDIFF passthrough)

To copy DST frames unchanged (for example into a DSDIFF file), read positions without
decoding them (specification 4, 4.6.1):

```rust
use scarletbook::FrameContent;

// A track's or range's positions as stored: DST bytes, plain DSD bytes, or missing.
let mut frames = disc.range_frames(Slot::TwoChannel, first, end)?;
while let Some(frame) = frames.next() {
    let frame = frame?;
    match &frame.content {
        FrameContent::Dst(bytes) => { /* the DST frame as stored */ }
        FrameContent::Dsd(bytes) => { /* C x 4704 plain bytes */ }
        FrameContent::Missing => { /* no frame: decoded reads fill it with 0x69 */ }
    }
    // Or one DST frame for every position, plain and missing ones included, that decodes
    // to exactly the position's audio.
    let dst = frames.dst_equivalent(&frame.content);
}
let missing = frames.missing_frames();
// Every accepted frame of the area, in frame number order, frames past the play time
// included; positions not listed are missing.
for frame in disc.stored_frame_list(Slot::TwoChannel)? {
    let frame = frame?;
}
```

`Disc::track_frames` does the same for a track. Positions, missing frames and malformed
sectors are exactly those of the decoded reads; invalid DST frames show only when decoded.
In C: `sb_raw_frames_open`, `sb_raw_frames_read`, `sb_raw_frames_read_dst_equivalent` and
`sb_stored_frame_list_open`, with caller buffers of at most `SB_MAX_FRAME_BYTES`.

### Seeking within an area

A range far into an area normally costs a scan of the area up to it: which frames a range
holds depends on every audio sector before it (specification 4, 4.5), so an exact reader
cannot skip ahead without having read them once. A **seek index** keeps the reading state
every 64 sectors, so that once it covers a range, opening that range reads only a few dozen
sectors before the range's own, wherever it lies (specification 4, 4.2 item 7). It is off
by default:

```rust
use scarletbook::{AreaIndex, IndexOptions};

disc.enable_seek_index(Slot::TwoChannel, IndexOptions::new())?;
// Reads build it as they go; or build it at once, in steps (one pass over the area):
while !disc.extend_seek_index(Slot::TwoChannel, 64 * 1024)? {}
// Every track and range cursor of the area now starts from it, with the same frames,
// counts and warnings as without it.
let audio = disc.range_audio(Slot::TwoChannel, first, end)?;
// Keep it for the next time this image is opened (about 24 bytes per 64 sectors).
let saved: Vec<u8> = disc.seek_index(Slot::TwoChannel).map(|i| i.to_bytes()).unwrap_or_default();
// ... later: from_bytes checks the bytes, set_seek_index the area.
let index = AreaIndex::from_bytes(area, disc.toc().sectors, &saved, scarletbook::seek::DEFAULT_INLINE_BUDGET)?;
disc.set_seek_index(Slot::TwoChannel, index)?;
```

A saved index is checked for safety (bounds, invariants, checksum, the area and image size
it belongs to) and, as it is used, against the image's sectors (a digest per checkpoint):
a mismatched index is discarded with a warning in the log and the area scanned from its
start. It is not proof against an index forged to match: keep it with the image it
describes. Every disc of one image (`Disc::share`, or `clone` of a disc read through a
`ReadAtReader`) uses and grows the same index, so to build it in the background, call
`extend_seek_index` on a clone in another thread while the others read; `AreaIndex::merge`
joins indexes kept apart, for example one loaded and one built.

A first seek into an area without a seek index still reads the area up to the range, which
over a network share can take seconds. A caller that accepts provisional positions can opt in
to **provisional reading** (specification 4, 4.2 item 8): `disc.set_seek_policy(slot,
SeekPolicy::Speculative(SpeculativeOptions::new()))` makes far ranges start after a short
search of the frame timecodes, a few small reads wherever the range lies, and read the range
in reads sized to it (one for a range of up to 1 MiB). Their positions are
marked provisional (`speculation()`): they equal a straight read on well-formed discs, but no
reader can know that without reading the sectors before the range, and on hostile images they
can differ (see `SeekPolicy`). Their malformed counts begin at the provisional start
(`counts_from()`). With a seek index enabled for the area, each provisional reading is
checked once the index reaches it (build it with `disc.verify_speculation(slot, sectors)`,
for example on a clone in another thread): confirmed, or refuted with the frame from which its
positions are exact; the cursor's `speculation()` and `disc.take_seek_events(slot)` report it,
so that a caller can drop and re-read what it served.

Features: `parallel` decodes DST frames on rayon's thread pool, ahead of the caller: the
current pool by default, or the pool chosen for a cursor with
`TrackAudioCursor::set_decode_on(DecodeOn::Pool(pool))`, whichever thread reads it
(`DecodeOn::CallingThread` keeps a cursor off every pool).

## C library

```c
#include "scarletbook.h"
struct SbDisc *disc;
if (sb_disc_open_file("disc.iso", &disc) != SB_STATUS_OK) puts(sb_last_error_message());
```

`sb_build_info()` says how the loaded library was built, for logs and bug reports: a
static string of `key=value` pairs naming its version, target, profile, features, target
CPU features, compiler and commit.

The conventions (status codes, copy-out strings, handle lifetimes, threads) are stated
at the top of `crates/scarletbook-ffi/include/scarletbook.h`;
`crates/scarletbook-ffi/examples/smoke.c` is a complete program. Calls return an
`SbStatus`, an `int32_t`; every struct field is a fixed-width integer (flags are `uint8_t`,
1 or 0) or, in `SbWarning`, a string pointer; and no struct has padding, so the layouts
stated in the header hold on every target. Regenerate the header with
`cbindgen --config cbindgen.toml --crate scarletbook-ffi --output include/scarletbook.h`
in `crates/scarletbook-ffi` (cbindgen 0.29.4; CI checks the committed header).

Beyond `SbDiscInfo`, `SbAreaInfo` and the strings, the master TOC's genres
(`sb_disc_genre`), text channels with their language codes as stored and character set
codes (`sb_disc_text_channel_count`, `sb_disc_text_channel`), catalogue numbers as stored,
padding kept (`sb_disc_catalog_number_stored`), and manufacturer data
(`sb_disc_manufacturer`) have calls of their own, as do an area's version, maximum
available channels, mute flags, track attribute and offset, and text channels
(`sb_area_details`, `sb_area_text_channel`).

`sb_disc_read_sectors(disc, lsn, count, buf, cap)` copies the 2048-byte user data of
logical sectors `[lsn, lsn + count)`, whatever the image's stored sector size (2048, 2054
or 2064 bytes): the bytes a 2048-byte-sector copy of the image holds there, for example to
digest the TOC sectors or write such a copy. A range reaching past the last sector fails
whole with `SB_STATUS_SECTOR_RANGE_INVALID`, writing nothing.

### Seeking

A seek index (see [Seeking within an area](#seeking-within-an-area)) is a handle of its
own, `SbSeekIndex`, tied to an area and image size rather than to a disc handle, so it can
be built on one disc handle and used on another of the same image:

```c
SbSeekIndex *index = NULL;
sb_seek_index_new(disc, slot, SB_SEEK_DEFAULT_INTERVAL, SB_SEEK_DEFAULT_INLINE_BUDGET, &index);
uint8_t complete = 0;
while (sb_seek_index_extend(disc, index, 65536, &complete) == SB_STATUS_OK && !complete) {}
SbTrackAudio *audio = NULL;
sb_range_audio_open_indexed(disc, slot, first, end, index, &audio); /* same frames, few reads */
/* ... sb_track_audio_read ... then hand its new checkpoints back: */
sb_track_audio_absorb(audio, index);
size_t len = 0;
sb_seek_index_save(index, NULL, 0, &len);  /* SB_STATUS_BUFFER_TOO_SMALL, *len set */
/* ... sb_seek_index_save(index, buf, len, &len); later
   sb_seek_index_load(disc, slot, buf, len, SB_SEEK_DEFAULT_INLINE_BUDGET, &index) */
```

`sb_range_audio_open_next_indexed` and `sb_raw_frames_open_next_indexed` continue a handle
through an index; `sb_seek_index_merge` joins indexes built apart.

A disc can also keep the index itself: after `sb_disc_seek_index_enable` (or
`sb_disc_seek_index_set` with a loaded one), every handle opened through the disc or any of
its clones (`sb_disc_clone`) starts from it, and reads build it, with no `_indexed` calls.
The disc and its clones keep one index, so `sb_disc_seek_index_extend` on a clone in a
thread of its own builds it for all of them; `sb_disc_seek_index_get` copies it out to
save. Loaded bytes are checked
before use, and an index that does not match the image's sectors is discarded as it is used
(a warning in the log, then a scan from the area's first sector).

Provisional reading (cold seeks, specification 4, 4.2 item 8) is opt-in per disc handle:
`sb_disc_seek_policy_set(disc, slot, SB_SEEK_POLICY_SPECULATIVE, SB_SEEK_DEFAULT_MIN_GAP)`.
After a handle's first read, `sb_track_audio_speculation` says whether its positions are
provisional (`SbSpeculation`). With a seek index kept, `sb_disc_seek_verify` (on a clone in a
thread of its own) checks provisional readings, and `sb_disc_seek_event_next` returns each
verdict once: confirmed, or refuted with the frame from which the positions are exact
(`exact_from`; re-read the positions below it with `SB_SEEK_POLICY_EXACT` for those of a
straight read). A disc that keeps a seek index of the area hands each reading through it to
that index, also for ranges opened with an index of the caller's.

### Parallel decoding

Track and range audio handles decode on the calling thread unless given a pool of
decoding threads:

```c
struct SbPool *pool;
sb_pool_new(4, &pool);                 /* 0: one thread per logical CPU */
sb_range_audio_open(disc, slot, 0, playtime, &audio);
sb_track_audio_set_pool(audio, pool);  /* continuations keep it */
sb_pool_free(pool);                    /* reference-counted: the handle keeps it alive */
while (sb_track_audio_read(audio, disc, buf, cap, &fi) == SB_STATUS_OK) { /* in order */ }
sb_track_audio_free(audio);
```

The calling thread still reads the disc (read callbacks run there) and receives the frames
in order, while the pool decodes DST frames ahead of it; the output is exactly that of the
calling thread. A handle holds at most `16 x threads` frames ahead, never more than 512
(about 48 MB at most). A pool may be shared by handles of several discs read on several
threads. The library creates no global pool; the log callback is also called from the
pool's threads (see `sb_disc_set_log`).

To read one image on several threads at once (for example several tracks of one disc),
give each thread a clone of the disc: `sb_disc_clone(disc, &copy)` shares the parsed TOC
and reads the same file or memory at a position of its own, and a track handle opened from
any clone may be read through any other. A disc opened with read and seek callbacks cannot
be cloned that way: open it with a positional read callback instead
(`sb_disc_open_callbacks_at`, called with an offset, possibly from several threads at once),
or give each clone read and seek callbacks of its own (`sb_disc_clone_callbacks`).

### Stored and decoded frames in one pass

A track or range audio handle can also give each position's stored content, as
`sb_raw_frames_read` gives it, next to its decoded audio, from one read of the area's
sectors (for example to write a file of the stored DST frames and decoded files at once):

```c
sb_range_audio_open(disc, slot, 0, playtime, &audio);
sb_track_audio_set_pool(audio, pool);   /* optional, as for any handle */
sb_track_audio_keep_stored(audio);      /* before the first read */
uint8_t raw[SB_MAX_FRAME_BYTES];
SbRawFrameInfo ri;
while (sb_track_audio_read_with_stored(audio, disc, buf, cap, &fi, raw, sizeof raw, &ri, 0)
       == SB_STATUS_OK) {
  /* buf: as sb_track_audio_read; raw[0 .. ri.size): as sb_raw_frames_read (1 for the last
     argument: as sb_raw_frames_read_dst_equivalent) */
}
```

The decoding runs where the handle decodes, with the same frames held ahead; the frames,
statuses, kinds and counts are those of the two separate handles, and each audio sector is
read once.

### Cancelling and progress

A conversion running on a worker thread can be stopped and followed from another thread,
through two small handles made for that, which several threads may use at once:

```c
SbCancel *token = NULL;
sb_disc_cancel_token(disc, &token);       /* on the disc's thread: shared by its clones */
SbProgress *progress = NULL;
sb_track_audio_progress(audio, &progress); /* on the handle's thread, before reading */
/* worker thread: while (sb_track_audio_read(audio, disc, ...) == SB_STATUS_OK) {...} */
/* other thread: */
uint64_t read, expected;
sb_progress_get(progress, &read, &expected); /* sectors read, sectors expected */
sb_cancel_request(token);                  /* e.g. on Ctrl-C */
```

While cancellation is requested, every call that reads audio sectors through the disc or
its clones returns `SB_STATUS_CANCELLED`, distinct from `SB_STATUS_IO`: at once for a call
that starts then, after at most 32 more sectors for one in progress (or, during the reads
sized to the range after a provisional start, after the read in progress, of at most 512
sectors, 1 MiB),
the scan before a range's first frame included, whatever the disc reads through (a file, memory or
callbacks). The request is sticky: it holds for the disc and its clones until
`sb_cancel_withdraw` (a disc opened afresh has a token of its own). The handles keep their
state: after `sb_cancel_withdraw` they continue exactly where they stopped; or free them. `sb_progress_get` gives the sectors a handle has read
(exact, updated at least every 32 sectors, or every read of at most 512 sized to a
provisional range, also during the scan before its first frame)
and the sectors it expects to read (an estimate, equal to the count read once done), for
track, range and raw frames handles. Neither handle borrows the disc or the handle it came
from, so polling it never collides with the reading thread; free each with its `_free`.

### Release assets

Each release carries the C library as `scarletbook-ffi-<version>-<target>.tar.gz`, with a
SHA-256 file `scarletbook-ffi-<version>-<target>.tar.gz.sha256`. Every one is built and
tested on its platform (`.github/workflows/clib.yml`): a C program linked statically and
dynamically, and Python's ctypes, decode a corpus image and compare TOC and audio with the
conformance manifest.

| `<target>` | Runs on | Built in |
|---|---|---|
| `x86_64-unknown-linux-gnu` | glibc 2.17 or later (manylinux2014) | manylinux2014 image |
| `aarch64-unknown-linux-gnu` | glibc 2.17 or later (manylinux2014) | manylinux2014 image |
| `x86_64-unknown-linux-musl` | musl 1.2 or later (musllinux_1_2), with `libgcc_s.so.1` | musllinux_1_2 image |
| `aarch64-unknown-linux-musl` | musl 1.2 or later (musllinux_1_2), with `libgcc_s.so.1` | musllinux_1_2 image |
| `x86_64-apple-darwin` | macOS 10.12 or later | `MACOSX_DEPLOYMENT_TARGET=10.12` |
| `aarch64-apple-darwin` | macOS 11.0 or later | `MACOSX_DEPLOYMENT_TARGET=11.0` |
| `x86_64-pc-windows-gnu` | Windows 10 or later; links with a UCRT MinGW-w64 GCC (MSYS2 UCRT64 or equivalent) | MinGW-w64 target |

The glibc builds are linked against glibc 2.17 itself, inside the manylinux2014 image, and
the build fails if the shared library asks for a newer glibc symbol version. The
macOS minimums are Rust's own for those targets. The Windows build uses Rust's MinGW-w64
target because its static library (`libscarletbook_ffi.a`) and import library
(`libscarletbook_ffi.dll.a`) are in the format MinGW-w64 GCC links; the DLL exports every
`sb_*` function (checked in CI) and depends only on Windows system DLLs. It uses the
Universal C Runtime (UCRT, `api-ms-win-crt-*.dll`, part of Windows 10 and later), so link
the static library with a UCRT MinGW-w64 toolchain (MSYS2 UCRT64 or equivalent); there is
no msvcrt variant.

Runtime dependencies on Linux: the shared libraries need `libgcc_s.so.1` (the unwinder) as
well as the C library. glibc systems have it as part of GCC's runtime (manylinux allows
it); on Alpine and other musl systems it is the `libgcc` package (`apk add libgcc`). The
static libraries list it in `native-static-libs.txt` (`-lgcc_s`).

The PyPA build images are pinned by digest; `.github/workflows/clib.yml` says how to move
to newer ones.

An archive unpacks to:

```
scarletbook-ffi-<version>-<target>/
  include/scarletbook.h
  lib/libscarletbook_ffi.a           static library (every target)
  lib/libscarletbook_ffi.so          shared library (Linux)
  lib/libscarletbook_ffi.dylib       shared library (macOS)
  lib/scarletbook_ffi.dll            shared library (Windows) ...
  lib/libscarletbook_ffi.dll.a       ... and its import library
  native-static-libs.txt             system libraries to link after the static library
  README.txt, LICENSE-MIT, LICENSE-APACHE
```

### Linking

```sh
# Static: the archive, then the system libraries it needs.
cc app.c -I$PKG/include $PKG/lib/libscarletbook_ffi.a $(cat $PKG/native-static-libs.txt)
# Shared: ship the library next to the program, or set an rpath.
cc app.c -I$PKG/include -L$PKG/lib -lscarletbook_ffi -Wl,-rpath,'$ORIGIN'
```

The Linux shared library has the SONAME `libscarletbook_ffi.so` and the macOS one the
install name `@rpath/libscarletbook_ffi.dylib`, so a program finds them through its rpath
(`-Wl,-rpath,@loader_path` on macOS). The SONAME is unversioned, since integrators ship the
library with their program; to be revisited at 1.0. With MinGW-w64 GCC,
`-lscarletbook_ffi` picks the import library (`.dll.a`), so the program needs
`scarletbook_ffi.dll` at run time; link the static library by its path instead to avoid
that.

### Using from Python (ctypes)

The library loads with Python's `ctypes`; there are no variadic functions, and every
type has a fixed ctypes counterpart. Check the ABI version first: the bindings below are
written for `SB_ABI_VERSION` 2, and a library of another ABI version must not be used
with them (see "ABI compatibility"). Give every function its `argtypes` and `restype`:
without them ctypes passes and returns C `int`, which truncates pointers and 64-bit values.

```python
import ctypes as C

lib = C.CDLL("/path/to/libscarletbook_ffi.so")  # .dylib on macOS, scarletbook_ffi.dll on Windows

SB_ABI_VERSION = 2  # the SB_ABI_VERSION of the header these bindings follow
lib.sb_abi_version.argtypes, lib.sb_abi_version.restype = [], C.c_uint32
if lib.sb_abi_version() != SB_ABI_VERSION:
    raise ImportError(f"scarletbook C ABI {lib.sb_abi_version()}, these bindings need {SB_ABI_VERSION}")

# The structs, field for field as in scarletbook.h (flags are uint8_t, 1 or 0).
class SbDiscInfo(C.Structure):
    _fields_ = [("sectors", C.c_uint64), ("sector_size", C.c_uint32), ("version_major", C.c_uint8),
                ("version_minor", C.c_uint8), ("album_set_size", C.c_uint16),
                ("album_sequence_number", C.c_uint16), ("hybrid", C.c_uint8),
                ("manufacturer_sector", C.c_uint8), ("year", C.c_uint16), ("month", C.c_uint8),
                ("day", C.c_uint8), ("area_count", C.c_uint32), ("warning_count", C.c_uint32)]

class SbAreaInfo(C.Structure):
    _fields_ = [(name, C.c_uint32) for name in (
        "slot", "kind_channels", "toc_lsn", "toc_sectors", "channel_count", "area_config",
        "sample_frequency_code", "frame_format", "max_byte_rate", "playtime_frames",
        "audio_start_lsn", "audio_end_lsn", "track_count")]

class SbTrackInfo(C.Structure):
    _fields_ = [("number", C.c_uint32), ("start_lsn", C.c_uint32), ("length_sectors", C.c_uint32),
                ("start_frame", C.c_uint32), ("duration_frames", C.c_uint32),
                ("start_flags", C.c_uint8), ("duration_flags", C.c_uint8), ("has_genre", C.c_uint8),
                ("genre_category", C.c_uint8), ("genre_index", C.c_uint8), ("reserved", C.c_uint8 * 3)]

class SbWarning(C.Structure):
    _fields_ = [("lsn", C.c_int64), ("slot", C.c_int32), ("track", C.c_uint32), ("code", C.c_char_p)]

class SbFrameInfo(C.Structure):
    _fields_ = [("number", C.c_uint32), ("status", C.c_uint32), ("dst_rule", C.c_uint32),
                ("size", C.c_uint32)]

class SbRawFrameInfo(C.Structure):
    _fields_ = [("number", C.c_uint32), ("kind", C.c_uint32), ("size", C.c_uint32)]

class SbGenre(C.Structure):
    _fields_ = [("category", C.c_uint8), ("index", C.c_uint8)]

    _fields_ = [("language", C.c_uint8 * 2), ("charset", C.c_uint8), ("reserved", C.c_uint8)]

class SbAreaDetails(C.Structure):
    _fields_ = [(name, C.c_uint8) for name in (
        "version_major", "version_minor", "max_available_channels", "mute_flags",
        "track_attribute", "track_offset", "text_channel_count", "text_charset")]

    _fields_ = [("claim", C.c_uint64), ("lsn", C.c_uint64), ("slot", C.c_uint32), ("state", C.c_uint32),
                ("first", C.c_uint32), ("last_returned", C.c_uint32), ("exact_from", C.c_uint32),
```

```python
def check(status):
    """Raises on a failure, with the calling thread's error message."""
    if status < 0:
        raise RuntimeError(f"{lib.sb_status_name(status).decode()}: {lib.sb_last_error_message().decode()}")
    return status

def disc_string(disc, field):
    """A disc string (SbDiscString), or None when absent: size it, then copy it."""
    n = C.c_size_t()
    if lib.sb_disc_string(disc, field, None, 0, C.byref(n)) == 2:  # SB_STATUS_ABSENT
        return None
    buf = C.create_string_buffer(n.value + 1)
    check(lib.sb_disc_string(disc, field, buf, len(buf), C.byref(n)))
    return buf.raw[:n.value].decode()  # may contain U+0000: use the length, not the NUL

disc = H()
check(lib.sb_disc_open_file("disc.iso".encode(), C.byref(disc)))  # a UTF-8 path
try:
    info = SbDiscInfo()
    check(lib.sb_disc_info(disc, C.byref(info)))
    title = disc_string(disc, 0)  # SB_DISC_STRING_ALBUM_TITLE
    audio = H()
    check(lib.sb_track_audio_open(disc, 0, 1, C.byref(audio)))  # 2-channel area, track 1
    try:
        buf = C.create_string_buffer(lib.sb_track_audio_channels(audio) * 4704)
        frame = SbFrameInfo()
        while check(lib.sb_track_audio_read(audio, disc, buf, len(buf), C.byref(frame))) == 0:
            dsd = buf.raw[:frame.size]  # interleaved DSD, channels x 4704 bytes
    finally:
        lib.sb_track_audio_free(audio)
finally:
    lib.sb_disc_free(disc)
```

ctypes releases the GIL for each call, so conversions on several Python threads run in
parallel: give each thread its own disc (or a clone of one, `sb_disc_clone`) and handles
(a handle may move between threads but not be used by two at once; an `SbPool`,
`SbCancel` or `SbProgress` may be shared), and read `sb_last_error_message()`
on the thread whose call failed, before that thread's next call, as `check` does. Every
handle has its `_free` function; nothing else needs freeing (the strings the library
returns are static or copied into your buffers). Callbacks (`sb_disc_open_callbacks`,
`sb_disc_set_log`) are `ctypes.CFUNCTYPE` objects: keep a reference to them until the disc
is freed, and catch every exception inside them: ctypes only prints it, and the library then gets
an unspecified value (for a read callback, return -1 instead). A log callback can be
called from a pool's threads (see `sb_disc_set_log`).
`.github/scripts/clib-smoke.py` checks the first block above against the header and runs it.

### ABI compatibility

The ABI is everything `scarletbook.h` declares (functions and their signatures, struct
layouts, enum names and values, macros) and the behaviour the header documents.
`SB_ABI_VERSION` in the header, and `sb_abi_version()` in the library, number its breaking
changes:

- **Additions keep `SB_ABI_VERSION`**: new functions, new types, new enum values (status
  codes included: treat a status you do not know as a failure) and new macros. A program
  built against an older header keeps working with the newer library.
- **Breaking changes increment `SB_ABI_VERSION` by one**: removing or renaming a
  declaration, changing a signature, changing a struct's layout (adding a field included:
  callers allocate the structs), changing an enum value, or changing documented behaviour
  incompatibly. The check below compares declarations as text, so it also counts renaming
  a parameter and reordering existing declarations as breaking; avoid both.
- Comments and documentation fixes that do not change behaviour are not ABI changes.

Releases follow this:

- a **patch** release (`x.y.Z`) does not change the ABI;
- a **minor** release (`x.Y.0`) may add to it, never break it;
- only a **major** release (`X.0.0`) may break it, and then increments `SB_ABI_VERSION`.

While the version is `0.y.z`, as in Cargo, the `y` step is the major one and the `z` step
the minor one, so there are no patch releases before 1.0.

A program checks `sb_abi_version() == SB_ABI_VERSION` before using the library. Since
additions keep `SB_ABI_VERSION`, a program that needs a function added in a later minor
release also checks `sb_version()`: the library must be at least that release. A program
that loads the library at run time can look the symbol up instead.

| `SB_ABI_VERSION` | First release |
|---|---|
| 1 | 0.1.0 to 0.3.0 (additions only in 0.3.0) |
| 2 | 0.4.0 (additions in 0.4.1 and 0.5.0) |

CI enforces this. `crates/scarletbook-ffi/abi/abi-N.txt` is the baseline of ABI version N:
the header's declarations without comments or layout. `.github/scripts/abi-check.py`
compares the header with the baseline of its `SB_ABI_VERSION` and says which case applies:

- a pure addition fails with "additive change: regenerate the baseline with --write". Run
  `python3 .github/scripts/abi-check.py --write` in the same commit, so the baseline always
  matches the header on `main`;
- anything else fails with "breaking change: bump SB_ABI_VERSION and add abi-(N+1).txt".
  Increment `SB_ABI_VERSION` in `crates/scarletbook-ffi/src/lib.rs`, regenerate the header
  with cbindgen (see above; editing the header alone fails CI's `--verify`), run `--write`
  to add the new baseline, and add a row to the table.

On a pull request, CI also classifies the header against the base branch's baseline of the
same version, so rewriting the baseline by hand does not hide a breaking change, and fails
if a baseline of an earlier version is edited, moved or removed.
`.github/scripts/abi-check-test.py` tests the check. A behaviour change that leaves the
declarations alone is invisible to it: bump `SB_ABI_VERSION` in `src/lib.rs` by hand,
regenerate the header (it then differs only in that line) and run `--write`.

#### From ABI 1 to ABI 2

ABI 2 (0.4.0) removes the declarations whose size or layout C leaves to the compiler, so
that every struct is the same on every target and every binding (ctypes, cffi, other
languages) can follow the header exactly. No function was added, removed or renamed. A C
program that uses the header's names needs changes only where it writes `enum SbStatus`
or passes a `bool *` for `complete`, then recompiles; a binding that spells out the types
follows every point:

- **Status.** Functions return `SbStatus`, now an `int32_t` (in C23 and C++, an
  enumeration with `int32_t` as its underlying type) instead of `enum SbStatus`. The
  `SB_STATUS_*` values are unchanged. Declare variables as `SbStatus`, not
  `enum SbStatus`; in ctypes, `restype = c_int32`. The other enumerations (`SbSlot`,
  `SbFrameStatus`, `SbFrameKind`, `SbDiscString`, `SbAreaString`, `SbTrackString`) are
  likewise `uint32_t`, as their arguments and fields already were.
- **Flags.** `SbDiscInfo.hybrid`, `SbDiscInfo.manufacturer_sector`, `SbTrackInfo.has_genre`
  and the `*complete` out-parameter of `sb_seek_index_extend`, `sb_seek_index_frontier`
  and `sb_disc_seek_index_extend` are `uint8_t` (1 or 0) instead of `bool`; pass a
  `uint8_t *` for `complete`. The header no longer includes `<stdbool.h>`.
- **Sizes.** `SbFrameInfo.size` and `SbRawFrameInfo.size` are `uint32_t` (at most
  `SB_MAX_FRAME_BYTES`) instead of `size_t`. The `inline_budget` arguments of
  `sb_seek_index_new`, `sb_seek_index_load` and `sb_disc_seek_index_enable`, and
  `sb_seek_index_memory`'s `*bytes`, are `uint64_t`, and so is
  `SB_SEEK_DEFAULT_INLINE_BUDGET`. `size_t` remains only for the lengths of caller
  buffers.
- **Layouts.** No struct has padding. `SbDiscInfo` starts with `sectors` (32 bytes, was
  40); `SbTrackInfo` ends with `uint8_t reserved[3]` (still 28 bytes); `SbWarning` is
  `lsn`, `slot`, `track`, `code` (still 24 bytes on 64-bit targets); `SbFrameInfo` is 16
  bytes (was 24) and `SbRawFrameInfo` 12 (was 16). Code that names the fields needs no
  change; a binding that lists them follows the new order.
- **`sb_dst_decode`** refuses a frame longer than `SB_MAX_FRAME_BYTES` (65 536 bytes,
  the reassembly limit of specification 4, 4.4.3) with `SB_STATUS_INVALID_ARGUMENT`,
  before reading it, instead of decoding it with memory proportional to its length.
  Frames from `sb_raw_frames_read` are never longer.

The check `sb_abi_version() == SB_ABI_VERSION` refuses a library of the other ABI either
way round.

## Measuring performance

`scarletbook-seekcost IMAGE` (in `scarletbook-conformance`) measures what opening a frame
range costs against where it starts, without and with a seek index, and the index's build
time and size. On a 50-minute 2-channel DST image (`scarletbook-synth --minutes 50 --area
2ch --kind dst`) a 14-frame range at 99 % of the area reads 470 272 sectors (146 ms from the
page cache) without an index and 64 sectors (2.4 ms) with one; the index (K = 64) takes one
pass to build (162 ms) and 178 KB saved. Its second table measures cold seeks by provisional reading (no index;
`SeekPolicy::Speculative`): on the same image, 2 to 4 read calls and 42 to 52 sectors
wherever the range lies, 1.8 to 2.9 ms in its network model (0.5 ms per read call, 110 MB/s),
with the same frames as exact reads on that well-formed image. Its third table opens the
disc afresh for each of 200 positions (`--positions`), as a consumer that seeks cold sees it:
on an area of uneven bit rate (`scarletbook-synth ... --dst-frames uneven`), a provisional
start costs 3.4 read calls and 81 KiB on average up to the range's first frame (at most 8 and
284 KiB), and 4.1 read calls and 126 KiB for the 14-frame range decoded.

Through the C interface, `python3 .github/scripts/clib-seekcost.py PACKAGE_DIR IMAGE` opens the
image with `sb_disc_open_callbacks` (counting read calls and bytes in the callbacks, 64 KiB per
read call) and decodes the same ranges cold, exact and provisional: on the same image, 4 to 7
read calls (164 to 285 KB, 3.5 to 5.6 ms modelled) for a provisional range anywhere in the area,
against up to 14 696 read calls (963 MB) for an exact one at 99 %.

Two criterion benchmarks track the decoder between releases:

```sh
cargo bench -p scarletbook --bench dst_frames             # DstDecoder::decode, one frame per iteration
cargo bench -p scarletbook --bench dst_frames -- stress/2ch
cargo bench -p scarletbook-conformance --bench pipeline   # Disc::open + TrackAudio, in-memory images
```

- `dst_frames` reports the time per frame and symbols per second (37 632 x channels per
  frame) for two sets, per channel count: `corpus/Nch`, every coded DST frame of the corpus
  images `dst-*.iso` that decodes; and `stress/Nch-LAYOUT`, 2- and 6-channel frames
  generated at start-up by the annex 5.A encoder of `crates/scarletbook/tests/common/dst_enc.rs`
  from a seeded sigma-delta signal (order-128 filters, order-32 filters, and a layout with
  several filter and ptable segments). The stress frames are identical on every run.
- `pipeline` reads every track of a 2-channel and a 6-channel area of small synthetic
  images (plain DSD, DST, DST in 2064-byte sectors) on one thread.

The scripts in `perf/` need Linux and `perf`:

| Script | What it does |
|---|---|
| `perf/cycles-per-symbol.sh [NAME...]` | cycles, instructions, IPC per decoded symbol and ms per frame for `dst_frames` benchmarks, from `perf stat` |
| `perf/flamegraph.sh NAME [OUT.svg]` | `perf record` and inferno (`cargo install --locked inferno --version 0.12.8`) flame graph of `DstDecoder::decode` |
| `perf/compare.sh REV_A REV_B [FILTER]` | builds two revisions (`.` is the working tree) into separate target directories, runs `dst_frames` alternately, pinned, and prints per-benchmark and per-group changes |
| `perf/build-configs.sh` | builds `bench` in several release configurations (LTO, codegen units, PGO) for generic x86-64, x86-64-v3 and znver5, and times single-thread decoding on synthetic images, alternately, pinned, best of several rounds |
| `perf/pgo.sh TARGET_DIR` | a deterministic profile-guided build of `bench` (needs `rustup component add llvm-tools-preview`) |

Pinning: run on an otherwise idle machine and pin to one CPU (the scripts use `taskset`,
CPU 2 by default; set `CPU=`). Turbo and frequency scaling still move results by a few
per cent between sessions, so compare only figures taken in one session, alternately, as
`compare.sh` does. `RUSTFLAGS="-C target-cpu=znver5"` builds for the measuring machine's CPU.

Which figures count: these benchmarks are for development and catch regressions; the corpus
frames are small test streams and the stress frames are synthetic. The figures against the
targets come only from the benchmark rounds on real discs recorded in sacd-spec
`benchmarks/README.md`. CI only compiles the benchmarks; it never times them.
